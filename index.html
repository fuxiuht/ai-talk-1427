04 信息差·书 · 单独深读
《知识的边界》· Too Big to Know · 戴维·温伯格

中信出版 · 网络时代的知识论

① 知识即网络

知识活在连接里

不再是书架上的固定物。谁连得上、谁滤得住、谁能在网里互相验证 —— 谁就有优势。企业团队的竞争力，很大一块是「连接质量」。

② 过滤器 > 库存

少而准，胜过多而乱

信息爆炸后，囤资料不如养过滤。收藏夹再厚，没有判断标准就是噪音。今天先讲信息感，再讲工具 —— 顺序刻意如此。

③ 权威在迁移

从盖章到可验证

权威从「机构盖章」转向「网络里可核对的出处与共识」。决策要追一手：论文、官方博客、可复现仓库 —— 而不是转述的情绪标题。

④ 企业怎么用

先信息感，再工具栈

团队先统一「怎么判断一条信息值不值得动」；再装少而精的 Agent / Skill。否则工具越多，被淹没得越快 —— 这是整场主线。

可引用：过滤器比库存更重要 · 先养信息感 · 再堆工具

06 工具 · 飞书 CLI · 深讲
让 Agent 真正动手
官方开源 · @larksuite/cli · 文档 / 多维表 / 日历 / 消息 / 任务
① Agent 动手

推理不够 · 要落动作

CLI 让 Agent 真的建档、查日程、回消息、回写群。

② Shortcut 优先

+verb 再 API

优先 Shortcut；其次已注册 API；最后裸调。写操作先出计划 · 人确认。

③ bot vs user

身份分清

--as bot 办群事；个人日历/私信用 --as user。

④ 群里办事

@bot 一条龙

妙记 → 待办 → 文档链接回群；敏感写操作单独审批。

⑤ 权限两层

应用 scope + 用户授权

发布新版本 → 管理员审批 · 最小 scope · auth status 核对

示例命令npx @larksuite/cli@latest install lark-cli docs +create --title "客户访谈提纲" lark-cli im +messages-send --as bot --chat-id oc_xxx --text "纪要已写好" lark-cli calendar +agenda --as user
